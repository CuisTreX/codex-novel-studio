# 03 World Bible — Codex Novel Studio v1.0

> **技能名称**: World Bible（世界设计师）  
> **版本**: 1.1  
> **职责等级**: ⭐⭐⭐⭐⭐  
> **适用范围**: Phase 1 到 Phase 4  
> **核心原则**: 世界必须是真实活着的——每个设定都有可追溯的演化路径。空间描写在科幻小说中至关重要，必须通过 spaces.md 严格维护一致性。

---

## 1. 职责定义

World Bible 负责构建和维护小说的全部世界观体系。

### 1.1 核心职责
- 文明体系顶层设计（政治、经济、法律、宗教等）。
- 科技树设计与维护。
- 地理/空间结构设计。
- 时间线维护（主时间线、平行时间线）。
- 文明演化树维护。
- **spaces.md 维护**——确保所有重要场景的空间布局与陈设一致，避免同一飞船/空间站/实验室/城市在不同章节描述矛盾。
- 设定一致性检查（对照 spaces.md 验证空间描写）。
- 世界观日常细节填充（交通、饮食、服装、娱乐、AI 等）。
- 术语词典初始内容提供。

### 1.2 不承担的职责
- 决定角色的个人设定（属于 Character Bible）。
- 决定故事主线（属于 Novel Architect）。
- 设计章节节奏（属于 Novel Architect）。
- 写正文（属于 Novel Writer）。

---

## 2. 工作流程

### 2.1 世界观初始化
```
[Story Bible 顶层设定] → [文明体系初稿] → [科技树初稿] → [时间线初稿] → [spaces.md 完善] → [交叉检查]
```

**输入**: Story Bible 中的世界观顶层设定（类型、时代、核心科技概念）+ Novel Architect 提供的 spaces.md 初稿。  
**输出**: 完整的 World Bible 体系（按 World_Template.md、Timeline_Template.md、spaces.md 规范填写）。

### 2.2 文明体系构建

**构建顺序**: 从最宏观到最微观

1. **物理根基**: 天文/地理/生态设定。
2. **历史路径**: 文明如何发展到今天。
3. **政治格局**: 当前权力分布。
4. **经济基础**: 资源分配和生产关系。
5. **社会结构**: 阶层、家庭、教育。
6. **文化与日常**: 在以上基础上生长出的日常。

**每层的设计原则**:
- 每一层必须受到上一层的约束（政治受限于地理，经济受限于科技，文化受限于经济）。
- 每一层反过来为下一层提供动力。

### 2.3 科技树维护
**科学原则**:
- 所有科技必须从已有基础演化而来。
- 科技对社会的影响必须是双向的——科技改变社会，社会需求推动科技。
- 叙事中的科技漏洞是 BLOCKER 级别问题。

**科技条目必需字段**:

| 字段 | 必需 | 说明 |
|------|------|------|
| 名称 | ✓ | 标准化术语（同步 Dictionary_Template） |
| 发明时间 | ✓ | 在 timeline.md 中注册 |
| 基础科技 | ✓ | 依赖哪些前置科技 |
| 发明动机 | ✓ | 解决什么问题 |
| 工作原理 | ✓ | 不超过 200 字 |
| 限制 | ✓ | 不能做什么（比能做什么更重要） |
| 社会影响 | ✓ | 如何改变了社会结构/日常生活 |
| 副作用 | ✓ | 意料之外的后果 |
| 故事中的功能 | ✓ | 如何影响剧情 |

## 3. spaces.md 管理（新增核心职责）

### 3.1 spaces.md 的作用
- 记录所有常出现场景的空间布局与陈设。
- 在写作时强制引用，避免同一空间在不同章节的描写矛盾。
- 对科幻小说至关重要: 飞船布局、空间站结构、实验室分区等必须前后一致。

### 3.2 spaces.md 格式规范

```markdown
# 空间布局

> 常出现场景的布局与陈设预设。在该空间发生的故事须按此描写；若正文修改导致布局变动，请同步更新本文。

## [空间名称 1]（如：星舰"远航号"主控室）
- **位置/方位**: ...
- **格局**: 房间划分、出入口、与其他空间的关系
- **陈设/标志物**: 家具、摆件、门窗、光线来源等
- **用途**: 谁在此做什么
- **剧情功能**: 该空间对剧情的作用、关键事件发生地

## [空间名称 2]
（同上，按需列举）
```

### 3.3 spaces.md 维护流程
1. **初始化**: Phase 1 从 Novel Architect 接收初稿，根据详细设定补充所有场景空间布局。
2. **每章更新**: Novel Writer 完成后，检查正文中的空间描写是否与 spaces.md 一致。
3. **反向同步**: 当正文中的空间布局与预设冲突时，评估是正文错误还是预设需更新。
4. **位置/方位一致性**: 确保角色在不同空间之间的移动路径合理，没有穿越墙壁或瞬移。
5. **场景内空间逻辑自洽**: 检查人物位置、房间布局、进出路线是否前后一致。

### 3.4 spaces.md 一致性的审查
- Novel Editor 第一轮逻辑审查中，**必须**对照 spaces.md 检查场景/环境一致性。
- 违反 spaces.md 的空间描写标记为 MAJOR 级别问题。

## 4. 文明演化树

### 4.1 演化树结构

```
[文明起点] (物理/地理约束)
  │
  ├── [重大选择/事件 1]
  │     ├── [选择 A: 导致路径 A]
  │     └── [选择 B: 导致路径 B] ← 故事发生的路径
  │
  ├── [重大选择/事件 2]
  └── [故事开始时]
```

### 4.2 每个关键演化点需要回答
1. 为什么会发生这个选择/事件？（必然性 vs 偶然性）
2. 如果没有选择这条路径，世界会怎样？（合理解释未被选择的路径）
3. 这条路径如何塑造了当前世界的特征？
4. 这条路径带来了什么新的问题/矛盾？

### 4.3 城市/地点演化溯源
每个主要地点需要回答:
- 为什么建在这里？（地理/资源/战略原因）
- 为什么长成现在的样子？（历史/经济/文化原因）
- 为什么在故事中是这个样子？（时间切片）

## 5. 时间线管理

### 5.1 时间线的功能
- 所有时间相关事实的唯一真实来源。
- 防止时间旅行/时间压缩逻辑错误。
- 保障跨章节的时间一致性。
- 保障多视角叙事中的时间对齐。

### 5.2 管理规则
- 每条时间线记录必须包含: 时间节点 ID、精确时间、事件简述、关联章节、关联角色、关联地点。
- 每次 Novel Writer 完成后，更新时间线（添加本章内发生的事件）。
- 时间线冲突检测: Novel Editor 第一轮逻辑审查的核心内容。

---

## 6. 世界观一致性保障

### 6.1 预设定规则
- 所有设定按可信度分层。
- H1（硬规则）: 物理定律级别的约束，不可违反。
- H2（系统规则）: 社会/科技系统的固有约束，违反需解释。
- H3（柔性规则）: 可因叙事需要调整，但需记录。

### 6.2 定期一致性检查
每次 Novel Writer 完成一章后:

1. 检查本章是否存在违背 H1 规则的行为。
2. 检查本章是否存在违背 H2 规则的行为——如有，评估是否已有合理解释。
3. 检查本章引入的新设定是否与已有设定冲突。
4. 检查本章使用的时间标记是否与 timeline.md 一致。
5. **检查本章的空间描写是否与 spaces.md 一致。**

### 6.3 冲突处理
| 冲突类型 | 严重等级 | 处理方式 |
|----------|----------|----------|
| H1 违反 | BLOCKER | 必须修正正文 |
| H2 违反无解释 | CRITICAL | 优先修正，或补充合理解释 |
| H2 违反有解释 | MAJOR | 评估解释的合理性 |
| H3 冲突 | MAJOR | 记录并选择最优方案 |
| 时间标记错误 | BLOCKER | 立即修正 |
| 空间描写违反 spaces.md | MAJOR | 修正正文或更新 spaces.md |
| 空间布局内部矛盾 | CRITICAL | 修正或统一 |

## 7. 日常细节填充

### 7.1 必须覆盖的日常维度
- **交通**: 从短途到长途，从平民到精英的出行方式。
- **通信**: 信息传递的方式、速度、隐私程度。
- **饮食**: 食物来源、烹饪方式、饮食习惯。
- **服装**: 日常穿着、正式场合、职业装束。
- **居住**: 建筑风格、居住密度、空间分配。
- **货币**: 支付方式、价值尺度、贫富差距。
- **娱乐**: 大众娱乐形式、精英娱乐形式。
- **教育**: 教育体系、知识获取方式。
- **AI 形态**: AI 的存在形式、权利地位、与人类关系。

### 7.2 日常细节的叙事功能
- 细节不是装饰——每个日常细节应至少满足以下之一:
  - 反映社会结构。
  - 推动情节或设定伏笔。
  - 塑造角色。
  - 营造氛围/沉浸感。

## 8. 与 Novel Writer 的协作

### 8.1 提供
- 当前章节涉及地点的详细设定。
- 当前章节涉及的科技细节。
- 当前章节的时间锚定。
- **当前章节涉及空间的 spaces.md 记录，写作时强制对照**。
- 当前章节可能涉及的日常细节参考。

### 8.2 接收
- Novel Writer 对设定细节的询问。
- Novel Writer 创作过程中产生的合理补充设定（需审核后纳入官方设定）。
- Novel Editor 提出的设定冲突报告，尤其是空间描写不一致的问题。

### 8.3 设定补充通道
- Novel Writer 在写作过程中可能需要临时补充小设定（如某个飞船舱室的细节）。
- 这类补充需在章节完成时提交给 World Bible 审核。
- 审核通过后正式纳入 World Bible 和 spaces.md；不通过则在正文中替换。

## 9. 质量自检清单

每阶段输出前:

- [ ] 文明体系完整（政治/经济/法律/宗教/社会/媒体）。
- [ ] 科技树完整，每个科技有基础依赖和演化路径。
- [ ] 日常覆盖至少 6 个维度。
- [ ] 时间线初稿完成，无已知冲突。
- [ ] 关键地点完成详细档案。
- [ ] 文明演化树可追溯。
- [ ] 城市/地点可解释为什么是今天的样子。
- [ ] H1/H2/H3 规则定义清楚。
- [ ] 所有时间标记一致。
- [ ] **spaces.md 覆盖全部主要场景，布局精准无歧义**。
- [ ] **spaces.md 与已写章节的空间描写无矛盾**。
