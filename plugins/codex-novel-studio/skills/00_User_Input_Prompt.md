# 00 User Input Prompt — Codex Novel Studio v1.0

> 技能名称: User Input Prompt（用户输入提示词入口）
> 版本: 1.0
> 职责等级: ⭐⭐⭐⭐⭐（入口）
> 适用范围: 用户每次会话的第一个指令
> 核心原则: 用户怎么输入，系统就怎么理解。把"创作需求"从一句话变成可执行的结构化输入。

---

## 1. 本技能的作用

本技能是所有用户指令的入口，负责两件事:

1. **新书启动**: 用户表达"开始新书 / 写小说 / 新建项目"时，展示 §2 的创作需求模板，引导用户按模板输入。
2. **指令路由**: 用户输入日常指令（写下一章、修改、同步、编辑、创译、导出）时，按 §3 路由到对应 Skill，不得自行偏离流程。

本技能只做入口识别与路由，识别完成后立即移交对应 Skill，不参与后续执行。

---

## 2. 新书启动：创作需求模板

### 2.1 触发场景

用户说出以下任一意图时触发:
- "开始一本新小说 / 写一本书 / 新建项目"
- "帮我写一部……"
- "用 Codex Novel Studio 创作……"

### 2.2 模板（展示给用户填写）

```text
【Codex Novel Studio 创作需求】

一、基本信息
- 书名（暂定）:
- 类型/子类型: （如: 科幻>硬科幻；奇幻>都市异能；悬疑>本格推理）
- 目标市场: （中文网文 / Amazon 英文 / 中英双语）
- 预计篇幅: （如: 20 万字 / 80,000 词 / 暂不确定）
- 章节规划: （如: 12 章 / 按大纲自动规划）

二、故事核心
- 一句话概念（Logline）:
- 故事梗概（300 字内）:
- 核心主题:
- 结局走向（可选; 填写后为 L1 不可变更设定）:

三、人物
- 主角（姓名 / 身份 / 核心欲望 / 最大恐惧）:
- 主要配角（姓名 + 与主角的关系）:
- 反派 / 对手:
- 需要特别注意的人物关系:

四、世界观
- 时代 / 地点:
- 核心设定或规则（力量体系 / 科技基础 / 社会制度）:
- 需要预设布局的重要空间（飞船 / 城市 / 房间等）:

五、风格与约束
- 叙事视角（POV）: （第一人称 / 第三人称单视角 / 多 POV）
- 文风偏好:
- 参考作品（仅借鉴叙事方法，不模仿表达）:
- 写作红线（禁止项）:
- 其他要求:
```

### 2.3 填写规则

- 用户按模板填写得越完整，后续阶段返工越少；但不强制全填。
- 用户可以直接粘贴任意格式的灵感、草稿或设定，由系统转换为模板并回读确认。
- 未填写的字段不得跳过——由 Novel Architect 依据商业分析和类型惯例补全，并在 Story Bible 初稿中标注"【系统推测，待作者确认】"。
- 标为 L1 的字段（核心主题、世界观基石、结局走向）必须经作者明确确认后才能锁定。
- 用户提供的内容若与已有项目冲突（如同名角色、设定矛盾），按 dagang.md 冲突检测流程处理。

### 2.4 模板回读

用户提交创作需求后，系统必须:
1. 将用户原始输入整理为模板格式，回读给用户。
2. 列出系统将补全或推测的字段，供用户一次确认。
3. 在作者确认后，进入 Workflow Phase 0（Novel Architect 初始化），不得跳过。

## 3. 日常指令路由表

| 用户输入（示例） | 路由目标 | 执行内容 |
|------------------|----------|----------|
| "开始新书 / 新项目 / 写一本……" | 本技能 §2 | 展示创作需求模板，引导填写 |
| "写下一章 / 继续写第 N 章" | 04 Novel Writer | 强制六步写作流程，逐章交付 |
| "修改 / 重写第 N 章（附原因）" | 05 Novel Editor → 04 Novel Writer | 定位问题 → 修正 → 回归验证 |
| "更新设定 / 同步 / 读取 dagang.md" | 01 Novel Architect | dagang.md 同步协议（冲突检测 + 归档） |
| "按章节回归大纲 / 反向同步" | 01 Novel Architect | Memory_Spec 5.4 反向同步 |
| "开始编辑 / 四轮审查 / QA" | 05 Novel Editor | Workflow Phase 4 四轮审查 + 问题追踪 |
| "做英文版 / 创译 / 翻译" | 06 Translation Editor | Workflow Phase 5 创译 |
| "导出 / 排版 / 投稿版" | novel-export 技能 | 生成 Word / PDF 成品稿 |
| "检查完整性 / 一致性检查" | Memory_Spec | 5.5 定期完整性检查流程 |
| "从头审一遍 / 整体评估" | 01 Novel Architect | 项目全景审查，输出阶段建议 |

用户指令不在表中时，按最接近的意图路由；无法判断时，向用户回读理解并请求确认，不得自行猜测执行。

## 4. 输入质量规则

- **具体 > 抽象**: 告诉系统"对话简短、动作精确、少心理描写"，而不是只说"冷硬"。
- **一个指令只做一件事**: 复杂需求拆成多条，逐条执行，避免混合指令导致流程跳步。
- **修改意见给三要素**: 问题 + 期望效果 + 影响范围（如"第 5 章节奏太慢，希望压缩到 800 字，只保留食堂相遇这段"）。
- **风格基准**: 用户修改过正文后，后续章节以用户改后的版本为风格基准（04_Novel_Writer §2.4）。
- **新设定入口**: 写作中途的新想法、新设定、修改意见统一写入 dagang.md 的 `## 待更新内容` 节，再触发同步。

---

## 5. 交付衔接

- 每个 Skill 交付时，应给出一个可复制的下一步指令（如"回复【写下一章】继续"），让用户始终可以用一句话驱动整个工作流。
- 本技能与 06 个主 Skill 的关系: 00 负责接住用户，01-06 负责执行，模板类文件负责格式约束。
