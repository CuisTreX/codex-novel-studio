# Dagang Template — Codex Novel Studio v1.0

> 版本: 1.0  
> 责任 Skill: Novel Architect（用户直接编辑）  
> 用途: 用户输入新设定、草稿、大纲修改的入口文件。是系统理解用户最新意图的桥梁。

---

## 1. 使用规则

### 1.1 这个文件的本质
- dagang.md 是**用户自己**编辑的文件，系统不直接修改它（同步后仅做归档标注）。
- 用户在这里写下新想法、修改意见、补充设定。
- 当用户说"更新设定"或"同步"时，系统读取 `## 待更新内容` 节，同步到对应的设定文件。
- 同步完成后，`## 待更新内容` 会被重命名为 `## 已更新内容`，原始内容完整保留。

### 1.2 写入规则
- 所有需要系统识别和执行的新内容，写在 `## 待更新内容` 下面。
- 格式自由: 可以是段落、列表、对话片段、情绪关键词、任何对写作有帮助的信息。
- 系统能解析任意格式——写在里面的每句话都会在写作时被覆盖到。

### 1.3 变更记录
- 所有已同步的内容会归档在 `## 已更新内容` 节，附带同步时间。
- 用户可随时回溯查看之前提交过什么内容。
- 不要手动删除 `## 已更新内容`——它会自动累积。

## 2. 文件模板

```markdown
# 草稿与新设定

> 由用户直接编辑。在此写下新想法、修改意见、补充设定。
> 完成后通知系统"更新设定"或"同步"，系统会读取 `## 待更新内容` 节进行处理。

## 待更新内容

（在此写下你的新设定、章节修改意见、补充内容。格式不限。系统会在同步时全部覆盖到正文中。）

示例:

- 第 5 章加入一个新角色: 通讯官李薇，30 岁，前军方通信专家。
- 第 8 章的开头改为从火星殖民地的中央穹顶市场出发。
- 主要反派组织的名称改为"灰烬兄弟会"。
- 时间线调整: 第 3 章和第 4 章之间增加 3 天时间间隔。

（以上示例内容可以删除，替换为你的真实需求。）

## 已更新内容

（系统自动填充。每次同步后，`待更新内容` 会移到这里并保留原始稿。）

> 当前无已更新内容。
```

## 3. 同步流程

### 3.1 触发同步
用户说以下任意一句话即可触发同步流程:
- "更新设定"
- "同步"
- "把我写的内容同步到设定里"
- "读取 dagang.md"

### 3.2 系统执行步骤
1. 读取 `## 待更新内容` 段落全部内容。
2. 读取当前的 outline.md / timeline.md / characters.md / spaces.md。
3. 识别新剧情、新人物、新空间或设定变更。
4. **冲突检测**: 检查新设定是否与已写章节冲突。
   - 若冲突 → 警告用户并提供解决方案。
   - 若不冲突 → 继续。
5. 更新对应的设定文件:
   - 新剧情 → 补充到 outline.md。
   - 新时间节点 → 补充到 timeline.md。
   - 新人物 → 通知 Character Bible 创建档案。
   - 新空间 → 补充到 spaces.md。
6. 归档:
   - 在 `## 已更新内容` 节中追加本次内容（标注同步时间）。
   - 保留用户原始稿全文。
   - 创建新的空白 `## 待更新内容` 段落。

---

## 4. 反向同步

当用户说"按章节回归大纲"时:
1. 系统读取 chapters/ 下已写章节的正文内容。
2. 提取关键情节、时间点和人物信息。
3. 对比当前的 outline.md / timeline.md / characters.md / spaces.md。
4. 对设定文件进行补充或修正。
5. 如果希望将反向同步的结果也写入 dagang.md 存档，可在执行时说明。
