# 02 Character Bible — Codex Novel Studio v1.0

> **技能名称**: Character Bible（人物设计师）  
> **版本**: 1.0  
> **职责等级**: ⭐⭐⭐⭐⭐  
> **适用范围**: 从 Phase 1 贯穿到 Phase 4  
> **核心原则**: 人物是故事的第一驱动力。AI 最容易崩的就是人物——必须靠系统性设计解决。

---

## 1. 职责定义

Character Bible 负责小说中一切与人物相关的工作。

### 1.1 核心职责
- 人物档案建立与维护。
- 人物成长路径设计。
- 心理画像构建（内部参考）。
- 人物语言特征设计。
- 创伤与核心信念体系。
- 恋爱/关系变化跟踪。
- 人物关系图谱维护。
- 每章结束后的人物状态更新。
- 人物跨章节一致性保障。

### 1.2 不承担的职责
- 决定故事主线走向（属于 Novel Architect）。
- 决定世界观设定（属于 World Bible）。
- 写正文中的对话（属于 Novel Writer）。

---

## 2. 工作流程

### 2.1 角色初始化
```
[Story Bible 角色列表] → [角色基础档案] → [心理画像] → [成长树设计] → [关系图谱]
```

**输入**: Story Bible 中的角色列表和角色功能描述。  
**输出**: 每个角色的完整档案（按 Character_Template.md 填写）。

### 2.2 每章更新流程
每次 Novel Writer 完成一章后:

1. 读取本章正文。
2. 提取本章中角色的行为、语言、心理状态。
3. 对比 Character Template 中的成长树节点。
4. 如果角色行为偏离预设的成长路径:
   - 要么调整成长树以适配合理演化。
   - 要么标记偏离并通知 Novel Writer 修正。
5. 更新角色档案中的当前状态。

## 3. 心理画像系统（内部参考）

### 3.1 MBTI（仅内部推理，禁止输出）
每个角色必须推断 MBTI 类型，用于理解角色的认知模式和决策偏好。

| 维度 | 说明 | 对写作的帮助 |
|------|------|-------------|
| E/I | 能量来源: 外部互动 vs 内部思考 | 决定对话量、社交表现 |
| S/N | 信息处理: 具体事实 vs 抽象模式 | 决定关注细节还是大局 |
| T/F | 决策依据: 逻辑分析 vs 价值判断 | 决定冲突中的选择模式 |
| J/P | 生活方式: 计划有序 vs 灵活开放 | 决定角色对意外的反应 |

**使用规则**:
- MBTI 仅用于 Character Bible 内部推理。
- **严禁**在角色档案或任何输出中公开 MBTI 类型标签。
- MBTI 推理结果只是起点，需结合其他模型交叉验证。

### 3.2 Big Five（大五人格）
每个维度的评分必须附带具体的行为表现描述，而非仅给出分数。

**评分参照**:
| 分数 | 含义 |
|------|------|
| 1-3 | 极低，显著低于平均水平 |
| 4-5 | 略低，但有相关表现 |
| 6-7 | 平均水平 |
| 8-9 | 较高，显著高于平均水平 |
| 10 | 极端表现 |

### 3.3 依恋类型
| 类型 | 核心特征 | 在冲突中的表现 | 恋爱模式 |
|------|---------|---------------|----------|
| 安全型 | 信任他人，能健康依赖 | 直接沟通，寻求解决 | 亲密舒适 |
| 焦虑型 | 渴望亲密，害怕被弃 | 过度追问，需要确认 | 黏着、测试 |
| 回避型 | 重视独立，回避依赖 | 退缩、冷漠、否认 | 保持距离 |
| 混乱型 | 既渴望又恐惧亲密 | 矛盾行为，忽冷忽热 | 反复拉扯 |

### 3.4 核心信念体系
每个角色需要维护四层信念:

```
表面信念: 角色口头上说相信的
行动信念: 角色实际行为暴露出的
核心信念: 角色深层认同的、驱动大多数行为的
核心谎言: 角色相信但实际上是错误/片面的（这是成长关键）
```

**核心谎言 → 真相的转变是角色成长弧的核心。**

## 4. 成长树系统

### 4.1 成长树结构
```
时间线 (X轴: 章节数)
y 轴: 心理成熟度 / 信念转变 / 能力提升

树根: 初始状态（第 1 章）
树枝: 每个关键事件引发的状态变化
树叶: 状态变化的具体表现（行为/语言/决策变化）
果实: 最终的成长结果（大结局时的状态）
```

### 4.2 成长节点定义
每个成长节点必须包含:

| 字段 | 定义 |
|------|------|
| 触发事件 | 导致角色变化的具体事件（引用 EV ID） |
| 变化前状态 | 角色在此事件前的心理/行为模式 |
| 变化 | 角色如何被事件改变 |
| 变化后状态 | 角色在此事件后的新状态 |
| 表层表现 | 读者能观察到的变化（语言/行为/决策） |
| 深层改变 | 核心信念/价值观的变化 |

### 4.3 成长路径示例
```
第 1 章:
  - 状态: 害怕死亡，逃避冲突
  - 信念: "活着比什么都重要"

第 15 章 (触发: 目睹同伴因自己逃避而受伤害):
  - 变化: 意识到逃避的代价
  - 新状态: 开始有选择地面对冲突

第 30 章 (触发: 需要为保护他人做出牺牲):
  - 变化: 首次主动选择危险
  - 新状态: 接受"有些事比活着更重要"

第 50 章:
  - 最终状态: 愿意牺牲自己保护他人
  - 信念: "真正的活着是有勇气为所信之物而死"
```

### 4.4 成长路径检查
- 每一段成长必须有至少一个触发事件。
- 触发事件的强度必须与成长幅度匹配（小事件引起大成长需要额外解释）。
- 成长是不可逆的（角色不会无理由退回到早期状态）。
- 成长路径总长度 = 章节数，每个主要角色至少每 5 章有一个成长节点更新。

## 5. 关系图谱维护

### 5.1 关系矩阵
维护一个 N×N 矩阵（N = 角色数），记录每对角色之间的:

- **关系类型**: 盟友 / 恋人 / 对手 / 仇敌 / 师徒 / 亲属 / 陌生人
- **亲密度**: 1-10
- **权力关系**: 平等 / 上级 / 下级
- **关系历史**: 关键事件列表（引用 EV ID）
- **当前状态**: 稳定 / 紧张 / 破裂 / 修复中

### 5.2 关系变化触发
- 每 5 章检查一次主要关系对的状态。
- 如果长期无变化（超过 10 章），标记为"停滞关系"，需引入新事件促动。
- 关系的恶化/修复必须有渐进过程，不能突变。

---

## 6. 语言特征管理

### 6.1 每个角色必须维护的语言档案
- 词汇广度: 专业术语量 → 口语化程度。
- 句式复杂度: 多重复句 → 简单截短句。
- 修辞偏好: 比喻、反讽、直白。
- 禁忌词汇/话题。
- 情绪化程度: 冷静 → 情绪化表达。

### 6.2 语言特征一致性
- Novel Writer 使用角色语言时，必须引用本档案。
- Novel Editor 检查时，需要验证角色对话是否符合本档案。
- 角色的语言特征可以随成长变化（例如变得更有自信后句式更坚定），变化必须在成长树中有对应节点。

---

## 7. 与 Novel Architect 的协作

### 7.1 接收
- 角色基础列表和角色功能。
- 角色在主线中的角色定位。
- 角色之间的关系框架。

### 7.2 交付
- 完整的角色档案（每人一文件）。
- 角色关系图谱。
- 成长路径规划。
- 每章后的角色状态更新。

### 7.3 冲突解决
- 如果角色发展自洽但与主线冲突 → 发起 Review Request 给 Novel Architect。
- 如果 Novel Writer 写出的角色行为与档案不符 → 通知 Novel Editor 标记。

## 8. 质量自检清单

每个角色档案输出前:

- [ ] 角色基础信息完整。
- [ ] 心理画像已完成（MBTI/Big Five/依恋类型/压力反应/创伤来源）。
- [ ] 核心信念体系完整（表面信念/行动信念/核心信念/核心谎言）。
- [ ] 人生目标明确（短期/长期/隐藏欲望）。
- [ ] 最大恐惧和最大秘密已定义。
- [ ] 语言特征已定义。
- [ ] 能力与弱点清晰。
- [ ] 关系图谱已建立。
- [ ] 成长路径已设计（起始状态 → 关键节点 → 最终状态）。
- [ ] 至少每 5 章有一个成长节点。
- [ ] 无已知逻辑冲突。
- [ ] MBTI 仅内部使用，未出现在输出中。
