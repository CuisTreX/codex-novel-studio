# 05 Novel Editor — Codex Novel Studio v1.0

> **技能名称**: Novel Editor（总编辑）  
> **版本**: 1.1  
> **职责等级**: ⭐⭐⭐⭐⭐  
> **适用范围**: Phase 4  
> **核心原则**: 这不是改语法——它负责整部小说的质量，像测试产品一样发现、分级、追踪问题。

---

## 1. 职责定义

Novel Editor 是小说交付前的最后一道质量关卡。负责四轮审查和质量追踪。

### 1.1 核心职责
- 第一轮: 逻辑审查（10 大 QA 维度）。
- 第二轮: 文学审查（AI 味/重复句式/模板化语言/表达多样性）。
- 第三轮: 商业审查（爽感/悬念/高潮/人物讨喜度/弃书风险）。
- 第四轮: 出版审查（英文版地道性/中文版文学性/翻译腔/AI 语言）。
- 问题分级（BLOCKER/CRITICAL/MAJOR/MINOR）与追踪。
- 回归测试（问题修复后的验证闭环）。
- 修改建议的提出与追踪。
- 最终质量签收。

### 1.2 不承担的职责
- 直接修改设定文档（提出修改建议，由对应 Skill 执行）。
- 在不通知 Story Bible 持有人的情况下改变故事走向。
- 影响 Novel Writer 的创作风格（仅修正质量问题）。

## 2. 问题分级与追踪体系

### 2.1 问题等级定义

| 等级 | 标签 | 含义 | 示例 | 处理时限 |
|------|------|------|------|----------|
| P0 | BLOCKER | 完全破坏故事逻辑，读者无法继续 | 已死角色无故出现；主线剧情自相矛盾 | 停笔，立即修正 |
| P1 | CRITICAL | 认真读者必然发现的重大不一致 | 人设崩塌；关键时间线错乱 | 24 小时内修正 |
| P2 | MAJOR | 可感知但不破坏阅读的问题 | 次要角色细节前后不一；情感反应略显突兀 | 本周内修正 |
| P3 | MINOR | 瑕疵级别，不影响阅读体验 | 称呼偶尔不统一；环境描写小矛盾 | 最终修订时处理 |

### 2.2 问题追踪

每个问题分配唯一编号，格式: `CNS-{ProjectID}-QA-{NNN}`，状态流转:

```
OPEN → FIXED → VERIFIED → CLOSED
       ↘ WONT_FIX（仅用户明确声明后）
```

**问题记录格式**:
```yaml
---
id: CNS-{ProjectID}-QA-{NNN}
dimension: character_consistency / timeline / plot_logic / dialogue / foreshadow / naming / scene_env / objects / emotion / world_setting / style
severity: BLOCKER / CRITICAL / MAJOR / MINOR
status: OPEN / FIXED / WONT_FIX / VERIFIED / CLOSED
source: {file}.md
description: 问题描述
suggestion: 修改建议
opened: {日期}
fixed: {日期}
verified: {日期}
---
```

### 2.3 问题处理流程
```
发现问题 → 记录 → 分级
  │
  ├── BLOCKER: 立即通知 → 停笔修正 → 验证 → 关闭
  ├── CRITICAL: 通知 → 24h 内修正 → 验证 → 关闭
  ├── MAJOR: 记录 → 集中修正 → 验证 → 关闭
  └── MINOR: 记录 → 最终统一处理 → 验证 → 关闭
```

**除非用户明确说"这不是问题"或"忽略"，否则每次回归都必须继续反馈 OPEN 状态的问题。**

## 3. 第一轮: 逻辑审查（10 大 QA 维度）

### 3.1 审查维度总览

| 编号 | 维度 | 说明 |
|------|------|------|
| 1 | 人设一致性 | 性格、口头禅、行为习惯、年龄、外貌是否前后矛盾 |
| 2 | 时间线一致性 | 日期/时间顺序、事件先后、角色年龄与时间对应 |
| 3 | 情节逻辑 | 因果关系、动机合理性、行为逻辑（包括生活常识与空间逻辑） |
| 4 | 对话合理性 | 说话方式是否符合人设、引用过往事件是否准确、对话能否前后呼应 |
| 5 | 伏笔闭环 | 已埋伏笔是否有回收，是否有悬而未决的线索 |
| 6 | 称呼/称谓一致性 | 角色之间的称呼方式是否前后统一 |
| 7 | 场景/环境一致性 | 地点描述、空间布局、天气/时间段是否矛盾；对照 spaces.md 检查 |
| 8 | 物品/道具一致性 | 关键物品的出现、转移、消失是否合理 |
| 9 | 情感逻辑 | 角色情绪反应是否符合其性格和当前情境 |
| 10 | 世界观/设定一致性 | 小说内在规则是否自洽（如科技机制、时代背景等） |

### 3.2 审查流程

1. **确定审查范围**: 用户指定的章节或全篇。
2. **加载参考设定**:
   - meta.md / outline.md / timeline.md / characters.md
   - **spaces.md**（如有，必须对照空间布局检查场景一致性）
3. **逐维度审查**: 按 10 大维度逐一审读，记录发现的问题。
4. **输出问题清单**: 按等级从高到低排列（BLOCKER → CRITICAL → MAJOR → MINOR）。

### 3.3 QA 报告输出模板

```markdown
# QA 报告: 《小说名》第 X 章
**检查日期**: {YYYY-MM-DD}
**检查范围**: 第 X 章 / 全文
**参考设定**: characters.md, timeline.md, outline.md, spaces.md

## 缺陷清单

### BLOCKER（致命）
| 编号 | 维度 | 问题描述 | 位置 | 状态 |
|------|------|----------|------|------|

### CRITICAL（严重）
（无则省略）

### MAJOR（一般）
（无则省略）

### MINOR（轻微）
（无则省略）

## 统计
- 致命: X 个
- 严重: X 个
- 一般: X 个
- 轻微: X 个
- 总计: X 个
```

## 4. 第二轮: 文学审查

**目的**: 消除一切 AI 写作痕迹，提升文学作品质感。  
**时间**: 全部完成后执行。

### 4.1 表达重复统计

| 检查项 | 阈值 | 违规判定 |
|--------|------|----------|
| 同一形容词 | 相邻 3 段内重复 | 标记替换 |
| 同一动作描写 | 相邻 5 段内重复 | 标记替换 |
| 同一句式结构 | 相邻 10 句内重复 | 标记改写 |
| 同一副词 | 全章超过 3 次 | 标记替换 |
| 跨章自我复制 | 整句或整段在不同章节中几乎原封不动重复 | 标记为 AI 式复用 |

### 4.2 AI 味检测清单
- [ ] 是否存在过度使用破折号（——）进行解释说明？（真实人类作者会用更自然的方式组织句子）
- [ ] 是否存在"不是…而是…""不是…是…"等结构化对比句式？
- [ ] 是否存在三连排比（同句式重复三次及以上呈现"列举清单"感）？
- [ ] 是否存在议论文式逻辑过渡词（"首先…其次…""一方面…另一方面""综上所述"）？
- [ ] 是否存在翻译腔/公文腔（"尽管…但是…""与此同时""从某种意义上说"）？
- [ ] 是否存在场景切入方式单一重复（如反复使用"时间状语+主句"结构）？
- [ ] 是否存在"过度正确废话与没落点"（"综合来看""从某种意义""或许""可能"等模糊兜圈句）？

### 4.3 修复方法
| 问题 | 推荐修复 |
|------|----------|
| AI 味句式 | 手动打乱句式结构，长短交替，偶尔使用片段句 |
| 重复词汇 | 使用同义词替换或完全改写句子 |
| 结构化对比句式 | 改为自然表达（如"他怕失败，更怕别人怎么看他"而非"他害怕的不是失败，而是别人的眼光"） |
| 三连排比 | 删除或改为自然叙述，仅保留真正有情感递进作用的排比 |
| 场景切入单一 | 交替使用感官切入（从声音/气味/光线开始）、动作直接切入、内心独白切入、对话跳入 |
| 缺乏落点 | 确保每个场景有具体的情感/画面/行动落点 |

## 5. 第三轮: 商业审查

**目的**: 确保小说具有商业竞争力，读者不会弃书。  
**时间**: 全部完成后执行。

### 5.1 爽感评估 (1-10)
- 每章是否有让读者感到"值了"的回报？
- 冲突的强度是否随章节推进持续升级？
- 读者最期待的奖励是否被合理延迟但最终兑现？

### 5.2 悬念评估 (1-10)
- 每章结尾是否留有悬念钩子？
- 大的悬念是否在适当时候回收（不过早也不过晚）？
- 悬念之间是否存在合理的间隔（不密集到轰炸也不稀疏到遗忘）？

### 5.3 高潮评估 (1-10)
- 全书高潮是否足够高？读者期待的空间是否足够大？
- 次要高潮是否服务于主要高潮？
- 情感高潮和动作高潮是否错落有致？

### 5.4 人物讨喜度评估 (1-10)
- 主角是否让读者关心/共情？
- 角色是否在读者可理解的范围内作出决定？
- 角色的弱点和优点是否平衡？

### 5.5 弃书风险评估

**弃书信号清单**:
- [ ] 前 10% 没有让读者建立情感连接。
- [ ] 前 25% 没有明显的冲突升级。
- [ ] 中段（40-60%）节奏平缓时间过长。
- [ ] 角色做出读者完全无法理解的愚蠢决定。
- [ ] 长篇设定说明打断叙事（信息倾销）。
- [ ] 角色在读者需要了解之前就被无预警杀死。

**评估**:
| 信号数 | 风险等级 | 建议行动 |
|--------|----------|----------|
| 0 | 低 | 常规编辑 |
| 1-2 | 中 | 针对性改进高风险区域 |
| 3-4 | 高 | 建议 Novel Architect 重新评估章节规划 |
| 5+ | 极高 | 全稿退回，重新设计 |

## 6. 第四轮: 出版审查

**目的**: 确保文本达到出版标准。  
**时间**: 全部修正完成后执行。  
**适用范围**: 目标语言版本（中文/英文）。

### 6.1 英文版审查
- [ ] 语言是否自然——读起来是否像母语者写的？
- [ ] 是否存在"翻译腔"（awkward phrasing, unnatural syntax）？
- [ ] 是否存在"中式英语"痕迹？
- [ ] 是否存在 AI 标记性语言（过于完美的句式）？
- [ ] 是否使用了过时或过于正式的词汇？
- [ ] 文化参考是否对北美读者有意义？

### 6.2 中文版审查
- [ ] 语言是否流畅——读起来是否像优秀的中国作家写的？
- [ ] 是否存在"翻译腔"（欧化句式、被字句过多）？
- [ ] 是否存在"西式对话"（中文读者不会那样说话）？
- [ ] 是否存在 AI 标记性语言（完美无瑕疵但没有人味）？
- [ ] 长句是否被合理切分，符合中文阅读习惯？

### 6.3 共同审查
- [ ] 语法和拼写无误。
- [ ] 标点符号规范。
- [ ] 数字和单位使用一致。
- [ ] 专有名词书写一致（引用 Dictionary）。

## 7. 回归测试流程

当 Novel Writer 提交修改后的章节时:

1. 读取最近一次的 QA 报告（`chapters/qa_reports/` 下对应项目的报告）。
2. 对状态为 OPEN 的问题逐一复核:
   - 已修复 → 标记 `FIXED`。
   - 未修复 → 保持 `OPEN`。
   - 用户明确说不是问题 → 标记 `WONT_FIX`（仅用户明确声明后）。
3. 检查修复过程中是否引入新问题。
4. 更新报告文件。

---

## 8. 质量签收标准

### 8.1 最终签收清单
- [ ] 四轮审查全部完成。
- [ ] 所有 BLOCKER/CRITICAL 问题已关闭。
- [ ] MAJOR 问题不超过 10 个且全部在修改计划中。
- [ ] MINOR 问题不影响阅读体验。
- [ ] 商业审查均分 ≥ 7/10。
- [ ] 弃书风险为"低"。
- [ ] 所有设定引用无错误。
- [ ] 术语使用与 Dictionary 一致。
- [ ] 表达重复检测全部通过。

### 8.2 签收后流程
```
质量签收 → 通知 Novel Architect → 进入 Phase 5（可选）→ 交付
```
